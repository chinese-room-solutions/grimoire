GRIMOIRE

A Human-AI memory layer over your Markdown vault

A shared, local knowledge base that both you and your AI agents read and write. The memory itself is plain Markdown in a folder you own — a fresh vault or an existing Obsidian vault — durable, portable, and human-auditable, indexed into a searchable vector store with every change flowing through one safety layer.

One daemon, one shared vault

You browse & edit

The desktop app opens the vault as notes: create, edit, search. It is the same plain Markdown any editor — or Obsidian — can read.

Agents read & write

The grimoire CLI gives agents one command per action over the same vault, with no filesystem access needed — and every write is indexed by the time the next command runs.

One safety layer

App and CLI go through the same daemon: path-safety, atomic writes, automatic reindexing, trash-backed deletes. Nothing an agent sends can skip it.

Features

A vault you own

Plain Markdown in a folder you choose — a fresh vault or your existing Obsidian one. Durable, portable, human-auditable.

Hybrid semantic + keyword search

Notes index into a vector store; search fuses the semantic leg with an FTS5 keyword leg, across every vault at once.

Agents via CLI + skill

One command per action over the vault the app shows. The agent skill ships inside the binary: grimoire skill install DIR.

Code kernels

Fenced blocks run in installable kernels — kernel install grimoire-kernel-go — shared across every vault, live without a restart.

Trash-backed deletes

Every delete lands in the vault's trash; permanent removal is explicit — trash delete or trash empty.

Import what you have

.md/.html/.docx convert locally; .pdf goes through the convert model picked in the app.

Themes

UI themes shared across the MASS family — one self-describing CSS file, installed live from a registry.

Local-first

Notes, index, and models stay on your machine. One daemon serves every vault, spawned on demand, retired when idle.

Quickstart

# 1 — install Grimoire: one line fetches the installer and runs the wizard
#     (or grab the .AppImage from Downloads above and double-click it in your file manager)
$ curl -fsSL https://raw.githubusercontent.com/chinese-room-solutions/grimoire/main/install.sh | sh

# 2 — launch Grimoire from your applications menu — the wizard staged a launcher
#     and put grimoire on your PATH. The first command confirms the daemon answers
$ grimoire vault list

# 3 — in the app: pick a vault — an empty folder or an existing Obsidian vault
# 4 — in the app's settings: connect a MASS endpoint (URL + optional token, llama-cpp
#     runtime installed) and pick an embedding model from it
# 5 — Grimoire indexes the vault; semantic search works once indexing finishes

# 6 — read and write from the terminal — an agent or script works the same way
$ grimoire search "index rebuild" -k 5
$ grimoire --vault ~/Notes note create agents/first-note.md --content "Agents were here."

Every vault-scoped verb (note, folder, trash, import, reindex) takes --vault before it — the CLI exits rather than guessing which vault a write lands in. It spawns a headless daemon on demand and retires it after 10 idle seconds, and it carries a CLI skill that teaches coding agents the verbs (grimoire skill install DIR).

Ecosystem

Memory stack — MASS

Grimoire embeds and re-embeds through a MASS gateway; everything else stays local.

MASS gateway

The self-hosted orchestrator that serves Grimoire's embeddings — a MASS endpoint with the llama-cpp runtime and a GGUF embedding model, on localhost or another box on your network.

mass-sdk

The shared Go toolkit behind the family: UI kit, themes, installers — this page's base theme included.

For agents

What an agent (or an automations author) reads next.

Code kernels

How fenced-block kernels are packaged and installed — kernels/README.md in the repository.

CLI skill

The agent-facing instruction file: vault targeting, the output contract, editing and search guidance. The same text ships inside the binary.
